## 1. 分支交付

- **场景**。加载固定版本的 FormDrive 2018 Tesla Model 3，展示银色车漆、暗棚反射、主光和落地阴影。拖拽旋转、滚轮缩放，并提供重置视角。加载时展示等待状态，失败时提供重试。
- **部件**。四门、四窗、前后备箱共十个部件各自开合。车窗沿车门滑动，玻璃下沉时隐藏进入门板的部分。车门打开时窗仍可升降。关闭动作回到资产的初始姿态。
- **点击**。区分轻点和拖拽，取车模最近可见表面，忽略静态车身和空白。车身上可见的热点随视角和部件更新。窗玻璃完全降下后，仍可点窗框热点升回。
- **界面**。全屏无外框展厅叠加半透明小窗。车门、车窗和备箱分组，四门和四窗各按方位排成 2×2。显示目标状态与动画进度阶段，支持全车门和全车窗动作。场景点击与面板点击走同一个控制器。
- **控制器**。实现已有的 `VehicleController` 契约，包括模拟引擎、稳定快照、同部件串行、按顺序执行语音批次和撤销未下发动作。开发验证页提供可独立验收的入口。语音、模型服务和生产入口装配分别由其功能分支和联调分支负责。

## 2. 接口与文件边界

| 产物 | 约定 |
| --- | --- |
| `src/scene/Showroom.tsx` | 导出 `Showroom`，遵守 `ShowroomProps`。模型节点绑定完成后报告驱动，卸载时解除绑定。拾取和热点均上报业务 `PartId`。 |
| `src/scene/model3Parts.ts` | 保存已锁定资产的节点名称、局部转轴与滑动参数。节点唯一匹配后才开始接收部件动作。 |
| `src/vehicle/vehicleController.ts` | 导出 `createVehicleController()`。稳定状态由驱动到位回执提交，失败与取消各有结果。驱动更换时废弃旧回执，部件同步到新模型的闭合初始状态。 |
| `src/ui/PartPanel.tsx` | 消费控制器快照，通过同一控制器发出单部件和组动作，禁用正在运动的部件入口。 |
| `public/models/` | 保存原始 GLB 和模型许可说明，移植的源码注明上游 MIT 许可。 |
| `dev/vehicle-interaction/` | 装配场景、控制器和控车小窗，供本地体验与浏览器验收。 |

左右按车辆前进方向定义。门和箱盖转动采用上游局部轴与角度。玻璃保持车门子节点关系，下降行程按玻璃高度和上游参数确定。对同一个目标重复下达语音动作时，控制器返回已到目标；组内并行，整组到位后继续下一条动作。独立部件可同时执行。

## 3. 独立验收

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| V01 | 打开验证页，拖拽和滚轮，重置视角 | 模型完整呈现，操作跟手，重置回到初始构图。拖拽松手和点击空白无部件动作。 |
| V02 | 从面板逐一打开并关闭十个部件 | 目标部件动画到位，其他部件保持各自状态，小窗同步反馈。 |
| V03 | 打开左前门并降下左前窗，再从窗框热点升起 | 门保持开启，窗玻璃随门并可独立升降。 |
| V04 | 点击可见门板、玻璃和箱盖，再操作全车门、全车窗 | 画面和小窗一致，批量动作覆盖对应四个部件。 |
| V05 | 使用模拟场景驱动测试队列、取消、失败、换场景和引擎状态 | 快照和结果与契约一致，旧驱动的回执不会覆盖新场景。 |
| V06 | 构建项目并验证子路径资源 | TypeScript 和 Vite 构建通过，模型资源可随 GitHub Pages 子路径加载。 |

V01–V04 对应需求 A02–A03。V05 支撑 A04、A07、A08 和 A11 的动作执行。正式页面及语音流程在联调阶段验收。
