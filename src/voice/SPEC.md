| 项目 | 约定 |

| 版本与日期 | v1.5，2026-11-04 |

## 1. 模块职责与接口

本分支实现浏览器语音输入、规则优先路由、模型工具客户端、运行时工具注册表、唤醒与确认状态机及半透明语音卡片。默认工具最终通过 `VehicleController.execute()` 提交动作。新模型请求与响应遵循 `shared/control.ts`，旧分类契约保留兼容。分支维护 `src/voice/**`、语音小窗和验证入口。

规则解析和语音流程支持注入识别输入、播报、模型客户端和计时器，便于用确定性输入独立验证。React hook 订阅稳定快照，卸载时终止本轮处理。默认输入为 `realtimeSpeech.ts`，经 AudioWorklet 采集 16 kHz PCM、通过 Worker WebSocket 连接中文 ASR。原有 SpeechRecognition 适配器保留用于兼容测试。前端仅配置公开接口地址，不保存识别服务 Key。

## 2. 唤醒、转写与状态

- 默认语音关闭。点击开启后，实际识别启动才显示等待唤醒。授权被拒、设备、网络或服务错误有中文提示，用户可重新开启。
- 唤醒词为「小满同学」，忽略识别文本中的空白与标点。支持唤醒词和指令同段返回，以及唤醒后由后续识别结果补充指令。识别服务将唤醒词拆成两段时，在 2 秒内拼接其前缀。等待唤醒时展示实时识别文字；识别未返回语音时提示检查麦克风输入。未唤醒的文本不提交车辆动作或模型请求。
- 唤醒后 5 秒内开始说指令。最终文本按识别结果序号去重并聚合，约 1 秒静默后处理一轮。正在说话或返回中间结果时继续收集。单轮收集设 20 秒上限，避免永久停在聆听状态。
- 状态包括未开启、启动中、等待唤醒、聆听指令、正在理解、播报建议、等待确认、执行中及异常。每条动作回调提供对应反馈。
- 识别会话自然结束时按当前状态恢复。用户关闭语音、取消本轮或重新唤醒时，撤销旧轮次的请求和未下发动作。迟到的识别、模型或动作回调按轮次丢弃。

## 3. 规则解析

| 输入示例（省略唤醒词） | 预期 |
| --- | --- |
| 打开左前门、关闭右后窗、降下左前车窗 | 生成对应部件的明确目标状态 |
| 打开所有车门、关闭全部车窗 | 生成门或窗的组动作 |
| 打开前备箱和后备箱 | 继承共享动作，按前后顺序生成两条动作 |
| 把左前车窗打开一点、右后车窗打开一半 | 将指定窗设为绝对开度 0.25 / 0.5，规则直接执行 |
| 所有车窗打开一半 | 四窗都到绝对开度 0.5 |
| 把车窗打开一点、车窗打开一半 | 本地生成对所有四窗的明确建议，语音确认后执行，不请求模型 |
| 关闭所有车窗熄火 | 支持无标点的相邻完整指令 |
| 打开左前门再打开 | 第一条执行，第二条提示缺少对象 |
| 打开、车门、开车窗 | 规则低置信度，交给模型追问缺少的动作或具体对象 |
| 不要打开左前门、取消 | 取消本轮 |
| 车里有点闷热、想透透气 | 模型结合状态返回具体工具调用 |

完整片段与白名单匹配才标记为 `high`，直接执行。`low` 和 `unmatched` 片段连同当前工具结构和状态交给模型。混合指令按顺序执行，已执行部分不重复送给模型。中间转写用于提示，最终转写才进入执行链路。

## 4. 模型建议与一次确认

客户端向配置的 HTTPS `VITE_INTENT_API_URL` 发送 `text`、当前 `tools` 和 `context`。开发环境可使用本机 HTTP 地址。模型通过 Function Calling 返回函数名和参数，后端及浏览器分别验证工具存在性和参数结构。

工具注册项包含定义、确认策略、状态读取和执行方法。首版注册部件、门窗整组和引擎工具，模型产生的车辆变更统一确认后执行。工具结构、状态和参数校验随注册表运行时读取，新增模块注册后即可供下次模型请求选择。扩展示例见 [TOOLS.md](./TOOLS.md)。

播报具体动作时暂停识别，结束并重新收到输入适配器 `onStart` 后启动 15 秒确认窗口。直接说「可以」「需要」「好的」可执行，说「不用」「不可以」「取消」撤销，无需再次唤醒。中间转写只展示；已开始回答时最多等待 10 秒的最终转写。肯定只消费待执行批次一次，含糊答复提示重说，否定、超时、新唤醒或关闭语音清除建议和剩余步骤。按钮为补充入口。窗口外单说「可以」无动作。模型工具及本地比例车窗建议共用该确认流程。

车窗「一点」「一点点」「一条缝」为 25%，「一半」为 50%，完全打开为 100%；均为绝对位置，重复请求不累加。普通「开车窗」继续按对象不明确处理。模型可调用 `set_window_openness(target, openness)`，取值须在 0–1 内。

### 连续对话

所有成功或已在目标状态的语音操作完成后，均进入 20 秒免唤醒窗口，包含明确规则动作。后续完整规则直接执行，未命中交给模型并携带上一动作上下文；每次完成重新计时。窗口内开始回答会等待其最终转写。超时清空上下文并回到等待唤醒，麦克风功能保持开启。尚未完成操作的模型澄清使用 60 秒窗口。

模型返回澄清问题后进入 `dialogue`，直接接收后续答复，不结束本轮。用户可短答窗位、幅度或继续调整，模型依据对话及最新工具状态选择动作。尚在澄清时 60 秒无答复结束；执行后按上述 20 秒窗口接收调整。说「好了」「结束」「不用了」终止，关闭或重新唤醒清空上下文。`dialogue` 消息最多 12 条，交替 user/assistant、每条最多 1000 字符、总计最多 6000 字符，在内存内滑动保留最近完整问答。每次模型请求携带之前的完整问答及当前文本，执行结果摘要也保存到上下文。

「再低一点」等相对表达保留完整原句送模型，依据当前开度增加 0.25，最大 1；「再高一点」减 0.25，最小 0，明确窗位沿用上下文，没有明确窗位则追问。相对动作转为绝对开度后确认及执行，自动重试仍复用同一绝对目标。

收到最终转写后即允许约 1 秒静默收尾，不依赖识别服务一定触发 speechend。识别适配器按句子 ID 去重最终结果及迟到的句首事件，避免停在聆听状态直至超时。

## 5. 工具结果反馈与重试

每条调用按 ID 返回成功、失败或未执行，并带副作用状态、错误码、重试资格和可读取的实际状态。独立项失败后继续处理其余独立项，保留全部结果。客户端以 `history` 回传，后端转换为标准工具观察消息供模型继续判断。

只允许模型重试初次失败且明确可恢复的原动作，名称及参数完全一致，使用新调用 ID；最多自动重试一轮。成功、取消、未执行、工具失效和不可恢复错误禁止重试。结果不确定时仅允许有状态观察的幂等工具重试。重试沿用原确认及原工具实例，不能引入新操作。关闭或取消后，迟到的重试响应不执行。

最终结果从实际回执计算，明确展示部分完成及仍失败的项。模型复核接口异常时，保留本地结果。初次规划至最终总结最多 3 次模型请求；每次都计入接口用量。协议及扩展约定见 [TOOLS.md](./TOOLS.md)。

## 6. 验证与交付

自动验证覆盖解析器、结果去重、5 秒唤醒超时、顺序执行、部分有效、自然结束后的恢复、确认／取消／超时、播报期间抑制识别、关闭后旧响应失效，以及接口格式与异常。

工具闭环另测三项两成功一失败、仅失败项重试、重试仍失败、重放与改参拦截、取消后迟到响应、模型复核不可用，以及结果不确定时的幂等与状态读取约束，对应 A18–A19。

开发验证页使用模拟车辆状态和可选模拟模型响应，可以切换到真实浏览器麦克风。验证页标明模拟状态。正式接线由联调分支在 `App.tsx` 注入真实车辆控制器。

完成本分支后运行 TypeScript 检查、生产构建和独立自动测试，记录命令与结果。真实浏览器麦克风、正式 HTTPS 模型接口与 3D 动画联动在集成环境验收 A04–A15。
