# 第二功能分支语音控制规格

| 项目 | 约定 |
| --- | --- |
| 版本与日期 | v1.0，2026-11-04 |
| 分支与工作区 | `codex/voice-control`，`../3DCar-voice` |
| 基线 | 需求 v1.3、架构 v1.2、公共基线 `03be34e` |
| 对外组件 | `VoicePanel`，接收公共 `VehicleController` |
| 独立验证入口 | `/dev/voice/` |

## 1. 模块职责与接口

本分支实现浏览器语音输入、中文规则解析、模型接口客户端、唤醒与确认状态机及半透明语音卡片。所有车辆动作通过 `VehicleController.execute()` 提交，目标窗口从控制器快照选择。模型请求与响应遵循 `shared/intent.ts`。分支维护 `src/voice/**`、`src/ui/VoicePanel.tsx`、对应样式和 `dev/voice/**`。

规则解析和语音流程支持注入识别输入、播报、模型客户端和计时器，便于用确定性输入独立验证。React hook 订阅稳定快照，卸载时终止本轮处理。默认浏览器适配器兼容 `SpeechRecognition` 和 `webkitSpeechRecognition`，识别语言为 `zh-CN`。

## 2. 唤醒、转写与状态

- 默认语音关闭。点击开启后，实际识别启动才显示等待唤醒。授权被拒、设备、网络或服务错误有中文提示，用户可重新开启。
- 唤醒词为「小满小满」，忽略识别文本中的空白与标点。支持唤醒词和指令同段返回，以及唤醒后由后续识别结果补充指令。未唤醒的文本不提交车辆动作或模型请求。
- 唤醒后 5 秒内开始说指令。最终文本按识别结果序号去重并聚合，约 1 秒静默后处理一轮。正在说话或返回中间结果时继续收集。单轮收集设 20 秒上限，避免永久停在聆听状态。
- 状态包括未开启、启动中、等待唤醒、聆听指令、正在理解、播报建议、等待确认、执行中及异常。每条动作回调提供对应反馈。
- 识别会话自然结束时按当前状态恢复。用户关闭语音、取消本轮或重新唤醒时，撤销旧轮次的请求和未下发动作。迟到的识别、模型或动作回调按轮次丢弃。

## 3. 规则解析

| 输入示例（省略唤醒词） | 预期 |
| --- | --- |
| 打开左前门、关闭右后窗、降下左前车窗 | 生成对应部件的明确目标状态 |
| 打开所有车门、关闭全部车窗 | 生成门或窗的组动作 |
| 打开前备箱和后备箱 | 继承共享动作，按前后顺序生成两条动作 |
| 关闭所有车窗熄火 | 支持无标点的相邻完整指令 |
| 打开左前门再打开 | 第一条执行，第二条提示缺少对象 |
| 打开、车门、开车窗 | 本地提示缺少动作或具体对象 |
| 不要打开左前门、取消 | 取消本轮 |
| 车里有点闷热、想透透气 | 进入模型意图判定 |

解析使用完整片段与白名单匹配。未知片段不能靠抽取其中的关键词产生车辆动作。有明确连接词时可分别判定片段，可靠的动作顺序提交，其余给出提示。中间转写仅用于反馈和判断开始说话，最终转写才进入执行链路。

## 4. 模型建议与一次确认

客户端向配置的 HTTPS `VITE_INTENT_API_URL` 发送 `{"text":"车里有点闷热"}`。开发环境可使用本机 HTTP 地址。只接受 `ventilate` 或 `unsupported` 两种意图。配置缺失、超时、取消、限流、服务异常或响应格式错误均有可理解的降级反馈。

收到通风意图后，按左前、右前、左后、右后顺序选择当前已升起且未运动的窗口，保存一个待确认动作。四窗均已降下时反馈当前状态。播报「要我帮你降下左前窗吗？」期间暂停识别，结束后启动 5 秒确认窗口，播报不可用时由文字提示接续。

确认窗口只接受明确肯定或否定，也提供「需要」「不用」按钮。肯定消费当前建议一次，向车辆控制器提交降窗动作。否定、超时、新唤醒或关闭语音清除旧建议。窗口外单独说「需要」按普通语音处理。建议产生到确认之间若车窗状态变化，按已说明的目标执行幂等降窗动作。

## 5. 验证与交付

自动验证覆盖解析器、结果去重、5 秒唤醒超时、顺序执行、部分有效、自然结束后的恢复、确认／取消／超时、播报期间抑制识别、关闭后旧响应失效，以及接口格式与异常。

开发验证页使用模拟车辆状态和可选模拟模型响应，可以切换到真实浏览器麦克风。验证页标明模拟状态。正式接线由联调分支在 `App.tsx` 注入真实车辆控制器。

完成本分支后运行 TypeScript 检查、生产构建和独立自动测试，记录命令与结果。真实浏览器麦克风、正式 HTTPS 模型接口与 3D 动画联动在集成环境验收 A04–A15。
